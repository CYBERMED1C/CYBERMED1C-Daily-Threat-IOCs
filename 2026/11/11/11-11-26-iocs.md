## Important campaigns and malware activity

**Falcon / Antino:** Unit 42's November 11 report supports browser-extension artifacts, C2 hostnames, delivery domains and an exact fake-update URL. The source describes March–May 2026 activity. Cisco Talos research dated September 30 independently corroborates two delivery domains and the Antino executable hash; it does not establish current activity.

**Citrus / Sn00py:** Kaspersky's November 11 report supports four malicious-file hash values and a keylogger-exfiltration/certificate-validation destination. Exact activity dates are unknown. Dual-use utilities and legitimate camouflage services remain excluded.

**FormBook:** One delivery document appears in CSIRT Italia's November 11 publication and independently retrieved sandbox evidence. Its observed execution proceeds from Word/Equation Editor through shell/CScript and PowerShell to FormBook-attributed descendant code. The provider first saw the file on November 10. Three hashes identify that one document.

**PureHVNC:** A public technical sandbox report explicitly records the original JavaScript file first seen on November 11. CScript/Explorer execution leads to a descendant containing malicious PureHVNC code. Separate file-observation context does not independently prove maliciousness. Three hashes identify one original script; child-memory and benign process hashes are excluded.

**njRAT:** CSIRT Italia's November 11 payload-delivery event matches an independently inspected technical record for a PE/.NET file masquerading as a spreadsheet. Selected behavior includes credential-store access and anti-analysis/memory changes. The family attribution comes from CSIRT; the separate provider uses a generic classification. Provider file observations are November 9–10. Three hashes identify one original file.

**macOS ClickFix:** Malanta's November 11 publication describes an October 20 fake-CAPTCHA chain, an exact shell-script URL, AppleScript persistence and a Polygon-resolved command server. Static analysis supports the behavior; the final payload was not retrieved. Public RPC and Cloudflare infrastructure are not treated as malicious roots.

**SSHole exploitation:** GreyNoise directly observed three source addresses executing post-exploitation commands during the Los Angeles report day. These are inbound SSH origins, with discovery or account/persistence actions beyond scanning. They are scoped to SSH port 22 in the hunts and are not treated as destination C2 addresses or assigned to a named actor.

## Coverage

The publication and file-validation workflow is operational. Research covered the four planned source categories and both passes. This is a bounded assessment of reviewed public evidence, not universal visibility or a statement that every listed value is currently active. Some primary appendices/detail pages were unavailable or gated; unsupported values were omitted.

Three Antino values have independent Talos corroboration. FormBook and njRAT original-file triplets combine today's government publication with separately inspected technical behavior. Other values retain their stated single-source or limited-corroboration status. `NEW` means first collected to this archive. Numeric confidence and acceptance scores remain unassigned; unknown lifecycle dates remain null.

The four Citrus file hashes are interpreted as MD5 from their 32-hexadecimal form because the primary appendix does not label the algorithm. OTX also classifies the exact records as MD5; that secondary type label supplies no independent maliciousness proof and no sample bytes were downloaded or hashed. MD5 and SHA1 are hunting identifiers, not modern integrity guarantees.

All five files use the same accepted set. Hunts use a rolling **30-day lookback** and a **500-result limit after IOC filtering**. Domains match exact hostnames; full URLs preserve the exact path and case. The Citrus IP maps to a destination. SSH attacker-source IPs map to remote peers on local port 22 in Defender and to `source.ip` with `destination.port == 22` in Elastic. Shared, reassigned or compromised addresses require local context before response.

Defender requires DeviceNetworkEvents, DeviceFileEvents and DeviceProcessEvents with the referenced fields. Source-IP hunting additionally needs endpoint visibility of inbound SSH peers and local ports. Elastic requires suitable ECS-mapped `logs-*` data including source/destination IP and port, domain/DNS, full URL, and file/process hash fields. Missing or conflicting mappings may require a narrower index/query. SHA256 and browser-resource hash events can be absent. No live Defender or Elastic parsing/execution is claimed. The 30-day window will not retrieve older activity outside retained queried data.
